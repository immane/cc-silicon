# T09: AST-to-CFG/IR Chips

Prerequisite T01; interfaces depend on T07 CheckedNode and T08 layout/init. Directory `chips/ir/lower/`. Reads typed AST/constants/layout/effects; writes IR and lower frames/proposals. The base IR is typed, explicit CFG, load/store, calls, and control terminators; the first version permits non-SSA — correctness first, optimization later.

`LowerRequest(node/function, current_block, value/address/discard_context)` → `LowerResult(value/address/blocks)`. All implicit conversions come from CheckedNode; use explicit ops to express signedness, overflow policy, volatile/atomic, alignment, and memory effects. Subtree lowering goes through tasks, with no mutual calls; after a block ends, ordinary instructions must not be appended again.

## Accepted upstream dependencies (operative)

These upstream shapes are **accepted subdecisions** recorded by the integrator (not T09 sign-off); T09 must consume them as stated and must not re-infer or duplicate them.

- **T07 semantic carrier.** `SemRecord` is the committed materialization of `CheckedNode`, **one per `NodeId`**, with an **explicit committed typed link consumed by T09** (CDR row F, user, 2026-10-05, rev 42). There is **no** `FunctionContextId`, and T09 must **not** create a `FunctionRecord` to obtain semantic facts (the T07→T09 handoff is the committed `SemRecord`, not a T09-created record). IR01 `FunctionBeginChip` still creates the **IR-stage** `FunctionRecord` for IR purposes after the sem stage; that is not a semantic facts source.
- **T08 constant split.** T08 computes the folded `int 5` (`ConstRecord.value`) from the **real committed `2+3` evaluation** (the frozen `ConstantRequest::Binary` inputs: committed operand `LiteralRecord`s + T07's checked `Add`); **T09 emits only the IR `Constant`** for it and does not recompute the value (H7). The T08→T09 handoff carries the committed `RecordRef::Const` (the same `ConstId`; OPEN-03 co-freeze, proposal rev 40) — not a bare projected index. The Part A folded-`int5` producer is separate from the probe-gated `M1-CL-02`, which is executed by chip `CL03` (`ConstantBinaryChip`), not by T09.
- **M1 conversion scope.** Only the **M1-minimal conversion scope** is frozen: M1-fixture-needed behavior including the identity/no-conversion rule. Integer promotions, float conversions (incl. `FloatToFloat`), pointer-qualifier conversions, and other non-M1 conversions are **explicitly unsupported/deferred** (distinct from silently omitting them) to a later append/contract revision (CDR row F, user, 2026-10-05, rev 46). No closed `ConversionOp`/`ConversionRole` list, `(op, role)` pairing, role→chip mapping, or numeric encoding is defined here. `IR07 ConversionLowerChip` must emit only the M1-minimal conversions; a non-M1 conversion is a typed unsupported/diagnostic, never a no-op.

## Candidate defaults and unresolved IR items (operative status)

The following are **integration candidate defaults selected under explicit user delegation** (2026-10-05, CDR rev 47). They are **not** a T09 owner sign-off and **not** a T01 `[INT]` acceptance; all remain **prospective `/6`**, pending **final T09/T01 co-freeze** and hashing. They are recorded here as the operative working basis only.

- **Rule aliases (candidate default).** Where the rejection→rule-id inventory had two unresolved aliases, choose the **shorter** ids: `ir.op-immediate-type` (not `ir.op-immediate-type-result-ty`) and `ir.terminator-missing` (not `ir.terminator-missing-explicit-commit-marker`). Every IR rejection still carries **one** stable rule id.
- **`Constant` validation precedence (candidate default).** When a `Constant` instruction is missing **both** its `immediate` and its `result`, validate the **immediate first** (`ir.op-immediate`). Checked pre-mutation in phase 2b.
- **`Constant` expected immediate type (candidate default).** The instruction's expected type equals its **result `ValueRecord.ty`**; the check is `ConstRecord.ty == ValueRecord.ty` (and the `ConstId` exists), with no host width and no lowering-context inference.

## `TerminatorMissing` completion fact (user decision, 2026-10-05; selected direction, not frozen)

This is the **explicit user decision of 2026-10-05** (`[OWNER:T09]` + T01 `[INT]`), recorded here as the **operative T09 direction**. It **supersedes the earlier marker-based wording for operative direction**; that wording is **retained below as history** and is no longer the operative trigger.

- **Deterministic completion fact = the IR28 `FunctionEnd` task's committed terminal result.** `TerminatorMissing` (an unterminated **entry block**) is decided from the **already-committed terminal result of the IR28 `FunctionEndChip` task** — i.e. `TaskState::Completed(ResultId)` carrying the **IR28 `FunctionEnd` task kind** — treated as the deterministic per-function **completion fact**. No explicit function-completion **marker record** is introduced: **do not add a record family, `Record`/`Id` type, backing arena, `RecordRef` variant/tag, `RecordFamily` variant/ordinal, snapshot encoder branch, or new `ResultValue` variant.** The completion fact is an existing committed T01 terminal task fact, not new IR schema.
- **T01-owned typed phase-2b commit-apply validation hook.** A **T01-owned typed phase-2b commit-apply validation hook** checks **entry block termination**: on applying the IR28 `FunctionEnd` task's terminal completion fact for a function, the phase-2b cumulative check verifies the function's **entry block is terminated** (has a terminator as its greatest `InstructionId`); only then is `TerminatorMissing` decided. The hook is a **T01-owned typed commit-apply validation**, not a T09 chip and not a new record. The hook's **rejection semantics and rollback ordering vs the selected H6 batch-failure recovery** remain open (**OB-26**; see the unresolved register).
- **Status: selected direction, not frozen schema or implementation authorization.** The **hook's exact typed contract/details and the `/6` hash treatment remain pending T01/T09 co-freeze**. This decision fixes the **direction** (reuse the committed IR28 terminal result as the completion fact + a T01-owned phase-2b entry-termination validation hook) and **nothing else**; it does **not** freeze the hook shape, phase/registration encoding, error carrier/rule-id, or any hash, and authorizes **no** implementation.
- **M1 fixture impact.** The **M1 positive folded-`int5` path does not rely on the `TerminatorMissing` negative fixture**; the **M1 `TerminatorMissing` negative fixture** exercises this **completion fact** (the committed IR28 `FunctionEnd` terminal result + the phase-2b entry-termination check). The **VF fixtures** for the completion fact/terminator (and the batch/terminator fixtures) remain **T13/T01 work** and **pending**; T09 does not define them.
- `UnsupportedNode`/`UnsupportedIrOp` remain **chip diagnostics**, not commit errors.

**Preserved as history (superseded for operative direction — do not act on).** The earlier text held that `IR28 FunctionEndChip` would commit an explicit **`CompletedFunction` marker record**, and that the marker's **record family/store/backing arena/`RecordRef` tag/snapshot encoder/`RecordFamily` variant** were **undefined** (H11), leaving the marker-based `TerminatorMissing` trigger a **selected direction** and a **T09/T01 `/6` blocker**. That history is retained only to show provenance; the 2026-10-05 decision **replaces the marker mechanism with the committed IR28 terminal-task completion fact plus a T01-owned phase-2b entry-termination validation hook**, so **no family/store/arena/tag/encoder/marker is to be invented or selected**. All IR rules/op-table/field shapes remain **prospective `/6`** and are not frozen or hashed by this document.

## M1-only IR shape checklist, one function (candidate, not frozen)

This checklist records the **M1-minimal IR shape** T09 must emit for the single M1 function, as the **operable T09 working basis**. It is **candidate/prospective `/6`**, **grounded** in the [M1 Part A proposal](M1_PART_A_CONTRACT_PROPOSAL.md) §5 IR block and [M1 target acceptance](M1_TARGET_ACCEPTANCE.md) §3.2, and is **not a T09 owner sign-off, not T01 `[INT]` acceptance, not a `/6` freeze**. No IDs, `RecordRef` tags, `IrOp`/rule numeric discriminants, enum ordinals, or `ResultValue` variants are invented here. The `FunctionEnd` completion direction preserves the user's H11 choice exactly (see below); **no** marker family is introduced.

**M1-only fields (candidate; names grounded in the proposal §5, exact encoding/typing open).** These enumerate the minimal fields the M1 shape needs; they are **candidate field names, not a frozen schema**, and every numeric/tag spelling stays an open T01/T09 `/6` co-freeze item.

- **FunctionRecord (one for `main`)** — `symbol: SymbolId` (the checked `main`), `signature: TypeId` (ABI-neutral `int (void)`, from the checked signature), `entry: BlockId` (the single entry block), `linkage` (external). Candidate, grounded in proposal `FunctionRecord { symbol, signature, entry, linkage }`.
- **BlockRecord (one, the entry block)** — `function: FunctionId`, `ordinal: u32`; instructions are **derived by ascending `InstructionId`**, not stored on the block. Candidate, grounded in proposal `BlockRecord { function, ordinal }`.
- **ValueRecord (the `Constant` result)** — `ty: TypeId` (the checked `int`); the producer is the **unique** producing `Instruction.result` (no stored `def`). Candidate, grounded in proposal `ValueRecord { ty }`.
- **InstructionRecord (M1 emits two, in order: `Constant`, `Return`)** — `op`, `block: BlockId`, `operands: Vec<ValueId>`, `immediate: Option<ConstId>`, `result: Option<ValueId>`. Candidate, grounded in proposal `InstructionRecord`. (`Add` is an op-table entry not emitted by the M1 fixture.)
  - **`Constant`** (op `ir.op.constant`): 0 operands, `immediate: Some(ConstId)`, `result: Some(ValueId)`, non-terminator. T09 emits only this IR instruction **for the constant value**; it references the **already-computed** `ConstRecord` (T08 owns `ConstRecord.value`, the folded `int 5`) and **does not recompute/refold** it. The delivered `ConstId` carrier is the committed `RecordRef::Const` (OPEN-03 co-freeze, proposal rev 40; resolves the OB-25 delivery-carrier choice); IR03 emitter attribution and the IR03 symbolic-vs-bit-pattern scope remain open.
  - **`Return`** (op `ir.op.return`): 1 operand for M1 `main` (the `Constant` result), `immediate: None`, `result: None`, the **unique terminator**; the terminator is the **greatest-ordered `InstructionId`** and nothing follows it.
  - **`Add`** (op `ir.op.add`): retained solely as the verifier/future two-operand form; **not required** by the M1 fixture (which emits the folded constant).
- **FunctionEnd completion result (candidate shape; committed IR28 terminal task fact).** `IR28 FunctionEndChip` produces the **committed terminal result** of its `FunctionEnd` task — `TaskState::Completed(ResultId)`, i.e. the task kind is `FunctionEnd` — as the deterministic per-function completion fact. The **result's typed payload shape, its `ResultValue` variant, and the task-kind/stage/depends-on typing are unresolved** and are not invented here; **no** `CompletedFunction` marker record/family/ID/arena/`RecordRef` tag/`RecordFamily` ordinal/snapshot encoder/`ResultValue` variant is added.

**M1 consumption rules (candidate).** T09 consumes the committed T07 `SemRecord` (the explicit committed typed link, one per `NodeId`, including the `Return` and `FunctionDefinition` nodes) without re-inferring, and consumes the committed T08 `ConstRecord` for the folded `int 5` **without refolding**. The folded `int 5` is the one produced by the **real T07→T08 evaluation** of the committed `2+3` inputs (`M1-CL-05`; frozen `ConstantRequest::Binary` operand/operator path, OPEN-03 co-freeze); a hand-built `5` is **not** the handoff. For M1 the conversions are the **M1-minimal** scope (identity/no-conversion only); a non-M1 conversion is a typed unsupported/diagnostic, never a no-op.

**M1 `FunctionEnd` / `TerminatorMissing` (preserves the user's H11 choice).** The completion fact is the **committed IR28 `FunctionEnd` task terminal result** (`TaskState::Completed(ResultId)`, task kind `FunctionEnd`), checked by the **T01-owned typed phase-2b commit-apply validation hook** that verifies the **entry block is terminated** (terminator as its greatest `InstructionId`). There is **no marker family and no new record/ID/tag/ordinal/encoder/`ResultValue` variant**; this is the **selected direction, not a frozen `/6` hook/schema**, and authorizes no code. The M1 **positive** folded-`int5` path does **not** rely on the negative fixture; the M1 `TerminatorMissing` **negative** fixture exercises this completion fact, and the **VF fixtures remain T13/T01 work and pending**.

**Unresolved (must not be treated as settled).** All of the following remain open T09/T01 `/6` co-freeze items:

- **FunctionEnd result typing / commit-hook validation order / error carrier.** The `FunctionEnd` terminal result's typed payload and `ResultValue` variant, the exact phase-2b commit-apply hook **ordering/typing**, and the error carrier/rule id for a failed entry-termination check (candidate short alias `ir.terminator-missing`) are unresolved; the hook's `/6` hash treatment is pending. The hook's **rejection semantics vs the selected H6 batch-failure recovery** are an explicit open blocker (**OB-26**, T09/T01; cf. OB-1): it is **not settled** whether a failed entry-termination check is a **task-scoped** failure (the IR28 `FunctionEnd` task fails exactly once without rejecting the whole batch) or a **whole-batch** `TerminatorMissing` rejection (H6: a failed semantic batch commit commits no semantic state), nor **how the "already-committed" completion fact can exist if the rejecting batch is rolled back**. No ordering is selected here.
- **IR record fields.** The exact field encodings/types of `FunctionRecord`/`BlockRecord`/`ValueRecord`/`InstructionRecord` (and their `*Draft` wire forms) are open; the names above are candidate, grounded only in the proposal.
- **Task/result typing.** The `ir.*` task kinds, stage/phase/depends-on typing, and payload variant spellings for IR01–IR28 (in particular IR28 `FunctionEnd`) are open.
- **Writer manifest.** The per-store/per-field write manifest for the T09-owned `ir` stores (`functions`/`blocks`/`values`/`instructions`), owner attribution, and read/write scope are open; the proposal's store table is a proposal, not a manifest.
- **Hash/rules/fixtures.** The `ir.*` rule ids and their hashed/`NORMATIVE_RULES` inventory, the two unresolved alias pairs (`ir.op-immediate-type`/`ir.op-immediate-type-result-ty`; `ir.terminator-missing`/`ir.terminator-missing-explicit-commit-marker`), the `/6` hash scope for IR rules/op table/fields, and the T13 VF fixtures (including the completion-fact/terminator fixtures) are pending.

**Status.** Candidate/prospective `/6` only; **rev-47 defaults and all other pending items preserved unchanged**; **no `/6` freeze, no `/5` change, no code**. ADR-0002 PROPOSED.
