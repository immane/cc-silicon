# T07: Expression, Statement Semantics, and Side-Effect Chips

Prerequisite T01; interfaces depend on T05 AST/T06 types. Directory `chips/semantics/`. Read AST/symbol/type/config and service results; write typed AST, conversion plans, value category and effect facts. Must not directly generate target instructions. Rule errors go through diagnostic proposals, do not panic.

> **Dependency-order correction (2026-10-05; no `/6` freeze, no code).** The original prerequisite clause named T08 constants as an upstream input. ### 2. T07→T08 per-use `ConstantRequest` ordering and `required_kind`

- The selected M1 stage order is **sem → const → ir**. T07 semantic checks produce the **per-use** `const.evaluate` `ConstantRequest`; T08 then computes/folds; T09 consumes the committed `SemRecord` **plus** the T08 constant. T07 reads **no** T08-produced `Const` fact as input on this path; the handoff is a committed next-tick reference, so there is **no `T07→T08→T07` cycle** (rev 44; T08 package rev 1/2; M1 rev 22 correction).
- **Frozen M1 request variants (OPEN-03 T01/T07/T08 co-freeze, 2026-10-05; proposal rev 40).** `ConstantRequest::Literal { literal: RecordRef::Literal, node, required_kind }` for a leaf-literal use and `ConstantRequest::Binary { node, op: ConstExprOp, lhs: RecordRef::Literal, rhs: RecordRef::Literal, required_kind }` for the binary additive use — each **references** the committed T04 `LiteralRecord`(s); the literal is not re-embedded; record-reference payloads only (T08 package rev 1; CDR §F4; proposal §5).
