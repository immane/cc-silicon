# T13: Verification Chips, Replay, and Differential Checking

Prerequisite T01, directory `chips/verify/`. Read each stage's records and freeze config, oracle inputs (sampled and injected by the Host); write verification facts/proposals. Chips must not execute GCC/programs/file reads; after execution the T00 Host feeds structured evidence into pins. The real report computing the final pass rate still belongs to T00; a verification chip passing does not mean the entire compiler passes.

Test evidence must cover both rule correctness and paradigm correctness. Invalid C may be used for diagnostic/recovery tests, without comparing arbitrary UB output; the original assertions of the frozen GCC torture are not to be deleted on one's own under this principle.

VF04 static AST lint, instrumented access, and snapshot diff are complementary tools: a simple before/after diff cannot prove that no unauthorized field was read; traits do not enforce ZST. Review and an auditable manifest cannot be replaced by lint. The VF12 Interpreter only verifies a covered subset, and Unsupported cannot be counted as equal; the final program is still generated by T11 and runs on the target.

## Framework-Level Mechanical Constraints Already in Place (Not the CompilerBus Implementation)

`cc-silicon::RestrictedChip`/`silicon_chip!`/`ChipAdapter`/`ProjectedChip` and `Motherboard::install_projected` provide a strict chip computation path: a chip has only `&Input` and typed Output, with no Bus access; the macro accepts only unit structs and performs a size=0 const assert; the adapter is explicitly responsible for projection and proposal submission. The old `LogicChip` still exists, retained for compatibility, and must not be used in new compiler chips.

The corresponding CI tests should be retained:

1. rustdoc compile-fail: field declarations, direct bus references, and modifying inputs should all fail to compile.
2. positive doctest: the macro declares the chip size as 0, and the computation result is normal.
3. integration test: restricted chip recomputes deterministically; proposals are submitted only through the adapter; wire reset/latch is still the motherboard's responsibility.
4. adapter permission test: changing a declared output field succeeds, and undeclared registers and register fields remain unchanged field by field.
5. application-level AST lint/dependency audit to be added later: prevent Host API dependencies, non-allowlisted crates, and cross-module calls between chips; when encountering an unanalyzable macro/dynamic path, it must strict-fail.

The AST-based checker is implemented under `tools/chip-lint/`. It has a dedicated test suite and scans a caller-specified chip-source directory. Its formatting, Clippy, and tests run in `.github/workflows/ci.yml`; no application chip tree exists in this framework-only repository to scan yet.

Current executable strict-path gates in the framework crate and lint tool:

```sh
cargo test --doc
cargo test --test paradigm
cargo clippy --all-targets -- -D warnings
cargo test --manifest-path tools/chip-lint/Cargo.toml
cargo run --manifest-path tools/chip-lint/Cargo.toml -- <compiler-chip-directory>
```

The checker rejects opaque macros in `compute`, unresolved/indirect bare calls, unsafe blocks, common Host/nondeterministic imports and paths, legacy LogicChip impls, non-unit `*Chip` structs, and obvious chip-to-chip tick calls. This is a conservative AST lint, not a proof: it cannot resolve all Rust aliases, method dispatch, re-exports, or transitive effects in called helpers/dependencies. Strict CI must still pin/allowlist chip-crate dependencies, keep Host code outside the chip crate, review helpers, and run deterministic replay tests. Unknown syntax fails closed; add reviewed rules/tests before widening an allowlist.

These guarantees have clear boundaries: Rust can constrain RestrictedChip code so it cannot see the Bus, but the current ChipAdapter still obtains a full Bus reference, so adapter field-level reads/writes cannot be guaranteed at compile time; to upgrade this layer into a strong guarantee, the CompilerBus schema needs to generate a per-chip private projection and typed patch setter. Pure functions are also not proven globally side-effect-free by the macro; crate dependency isolation, lint, and replay tests are still required.

## Verification Engineering Deliverables (Non-Chip Host Tests)

1. Per chip: all tests in the case table, at least one mutation regression (the test can fail when the rule is deliberately broken).
2. Per stage: real upstream/downstream signal integration, cross-tick result persistence, unauthorized stores unchanged.
3. type/layout/ABI: reference probes for the same target and two-way mixed linking.
4. preprocess/token/typed AST/IR: stage dumps support first-divergence localization, dumps are stable and do not depend on host pointers.
5. optimize: generate well-defined programs, before/after IR and target-execution differential; fenv/NaN/alias and other high-risk items in separate cases.
6. extensions: positive/negative tests in standard/GNU mode, and each corpus failure's owner chip IDs are traceable.
7. regression: the original GCC cases must not be modified; reduced cases and proptest seeds are retained; the full matrix is rerun.

ProofObligation/Counterexample class chips may continue to be added, but it must not be claimed that the current task has completed a formal proof. 99% is engineering acceptance on a frozen test corpus, and does not mean 99% of all C programs are correct or that there are "mathematically no bugs".
